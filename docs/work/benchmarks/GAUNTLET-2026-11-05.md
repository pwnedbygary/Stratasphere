# Benchmark gauntlet — Strata on the RX 9070 XT

**Date:** 2026-11-05 · **Hardware:** Ryzen 7 7800X3D, 30 GiB usable RAM, Radeon RX 9070 XT 16 GB (gfx1201), ROCm 7.2.4, CachyOS.
**Engines:** router AppImage built from the merged branch (`strata-native`, engine 0.1.56); DeepSeek on `strata-dsv41` 0.1.56.
**Method:** the repository's own gauntlet, `tools/coding_context_bench.py` — a coding prompt filled to 8,192 or 32,768 tokens
that holds three retrieval checkpoints, a fresh answer (up to 768 tokens), then an identical-prefix follow-up;
greedy sampling, thinking disabled; then `tools/check_coding_context.py` runs the 13-check code suite on the fresh answer.
One run per cell, desktop sharing the GPU, no repeats — treat differences under ~5% as noise.

## Verdict — fastest with good code quality

1. **Flash-Next Coder IQ1_M is the fastest 8K coding model once its page cache is warm**: 73.1 tok/s decode
   (1,067 prefill), just ahead of Saluki, with 12/13 code checks and 3/3 retrieval; at 32K its prefill is far the
   fastest (2,540 tok/s) but decode drops to 38.0. It needs the app server (not the native router), and its first
   answer after a fresh download was slow (303/23.6) until the files were cached.
2. **Saluki 27B IQ2-mix + MTP remains the best all-round pick**. Fastest decode at both sizes (72.3 tok/s at 8K,
   62.4 at 32K), fast prefill, full 13/13 code checks and 3/3 retrieval at both sizes, and the MTP drafter accepts
   nearly every draft (220/226 and 224/230).
3. **Swift 1.5 IQ3_XXS + MTP** is the quality-leaning alternative: 67.9/59.9 tok/s, also 13/13 and 3/3 at both sizes —
   about 6% slower than Saluki, with a higher-bit quant.
4. **Swift 1.5 IQ3_S + MTP**: 67.3/58.5 tok/s, 13/13; the same family with the largest (slowest) quant of the three.
5. **Cyber-Tiel Coder** has the fastest prefill by far (1,844–1,859 tok/s — good for very long prompts), but ~31 tok/s
   decode, and it misses the same boundary check at both sizes: `next_head((0,0), (1,0), 2.5, 4)` returns `(1.0, 0)`
   where a non-cardinal step should raise `ValueError`. It is the right choice only when prompt reading dominates.
6. **Flash-Next Unsloth UD-IQ3_XXS**: 13/13 quality but 7.8 tok/s at 8K and 5.0 at 32K — not interactive on a 16 GB card;
   its cold prefill is ~254–325 tok/s.
7. **DeepSeek V4.1 Coder**: 13/13 but 2.1 tok/s at 8K on this RAM — keep it for batch work only.

## Notes and limits

- One run per cell; the desktop was using the GPU; no repeats, so small differences are noise. 128K context and
  concurrent-request throughput were not tested.
- Flash-Next's first 8K request after load returned `finish_reason=length` with 0 tokens (a template/first-request
  quirk); the repeat passed 13/13 and is the figure used. Its first cold prefill: 254 tok/s.
- Cyber-Tiel's first 32K attempt got a 503 during the model switch; the isolated rerun succeeded (figures above).
- Full raw evidence: `summary.json`, and each model's `report.json`, `fresh.md`, `checks.json`, `retrieval-check.json`,
  `memory.jsonl`, `fresh.sse` in this folder.
- The vision paths of these models were separately verified on 2026-11-05 (each encoder encoded the repository's
  `shapes.png`; see `/home/garyb/Mounts/NVME/LLMs/README-models.md`).

## The Coder IQ1_M memory-admission note

The profile `flash-coder-iq1_m` (vision, MTP, int8 KV, `--resident-experts`) is the recipe the app and Terminal use.
Under the fork's native C++ router (`strata-native`), the same profile is refused at long prompts:
the router's admission guard cancels the request ("Insufficient process memory budget") once the resident expert
tier plus prompt buffers exceed its process budget; a `--ram-cap 22` run let a 62-token request through but still
cancelled an 8K prompt, and the engine fell back to 12.7 GiB resident / ~20 tok/s. The working path is the app's
`serve/server.py` with the same config (~17.5 GiB resident, no file reads, 73 tok/s warm), available here as
`~/.local/bin/strata-coder` (port 8097). The router registry therefore does not include this profile.

Reading the max-context table:

- **Coder IQ1_M is the best at a full 128K**: 2,170 tok/s prefill and **54.8 tok/s decode**, only one boundary check short
  of perfect. Its prefill is ~3x Saluki's and its decode beats every other model at this window.
- **Saluki degrades gracefully** (49.2 decode at 128K vs 72.3 at 8K, 13/13): the best all-round long-context model.
- **Swift is the surprise loser at 128K**: IQ3_S falls to **13.0 tok/s** from 58.5 at 32K, IQ3_XXS to 20.4 from 59.9 —
  their KV at 128K squeezes the expert cache, so most experts stream from RAM/SSD each token.
- **Cyber-Tiel holds 260K** at 970 prefill / 24.2 decode and now passes all 13 checks (its 32K run missed `next_head`).
- **Flash-Next Unsloth is unusable at 128K** (4.9 tok/s) — the hybrid expert streaming dominates.
- The 2,048-token answer margin means each test leaves room for the 768-token answer and the follow-up; none hit a
  context-limit refusal.
- ¹ **DeepSeek at 1M, stopped by choice.** Its 1M config starts and runs (`context 1048576 tokens`; the KV takes
  0.97 GB of VRAM and the expert cache falls to 3.35 GB / 351 experts), but the Coder set's prompt path streams
  ~7,300 experts from the SSD on this 32 GB-RAM PC: **555,968 of 1,046,486 prompt tokens in 1,617.9 s (~344 tok/s)**,
  i.e. about **51 minutes to the first token** in total (23 more minutes were left when the run was stopped), and
  ~2.1–2.3 tok/s decode after that. That is expected: the docs say a 512K/1M first reply takes many minutes even on
  adequate hardware, and this PC is below DeepSeek's 46 GB RAM minimum. The practical DeepSeek data points remain the
  8K run (203 tok/s prefill, 2.1 tok/s decode, 13/13 code checks) and the ~31K test (1.8 tok/s decode).



## Addendum (2026-11-05, later): Cyber-Tiel MTP enabled

After this gauntlet, Cyber-Tiel's in-file MTP block was enabled through a local opt-in router patch (commit
`c3f5f5c5`, profile `inference.allow_mtp`). With the full profile (262,144 context, vision, ubatch 512) it now
decodes **59.5 tok/s at 8K** and **38.3 tok/s at a 260,096-token prompt** (748.9 tok/s prefill), with 12/13 code
checks at both. The tables above are the pre-MTP baseline; details and the ubatch-1024 VS 512 memory trade are in
`../mtp-test/RESULTS.md`.
